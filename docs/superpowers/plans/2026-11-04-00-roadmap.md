# Roadmap — How You and Claude Build the Nutrition Shopping Planner

**Spec:** `docs/superpowers/specs/2026-11-04-nutrition-shopping-planner-design.md`

The app is built in 7 plans, in order. Each plan ends with something that works and is tested. Claude writes the detailed plan for each phase right before it starts, so each plan uses what was learned in the previous one. Plan 1 is written: `2026-11-04-01-nutrition-engine.md`.

Legend: **🧑 You** = something only you can do (accounts, keys, approvals, testing on your phone). **🤖 Claude** = code, tests, commands.

---

## Phase 0 — One-time setup (about 30 minutes, 🧑 You)

1. **Install Node.js (LTS version)** from https://nodejs.org → "LTS" → run the Windows installer with default options. Close and reopen the Claude app afterwards so it sees Node. *(Git is already installed on your PC.)*
2. **Create a GitHub account** at https://github.com (free). This is where the code lives; Vercel deploys from it.
3. **Create a Vercel account** at https://vercel.com → Sign up → "Continue with GitHub" → choose the free **Hobby** plan.
4. **Create a Supabase account** at https://supabase.com → "Start your project" → sign in with GitHub. (Free tier. Note: free projects pause after about a week of no use; you un-pause with one click in the dashboard.)
5. **Get a free USDA FoodData Central API key** at https://fdc.nal.usda.gov/api-key-signup → you receive the key by email. Keep it private; you'll paste it into a settings file when Claude asks (never into chat history you share publicly).

You can do steps 3–5 later — they're first needed in Phases 2–3. Only step 1 is needed to start Phase 1.

---

## Phase 1 — Nutrition engine (Plan 1) — the "brain", no screens yet

- 🤖 Sets up the project, writes the nutrient reference data (official DRIs), builds the ~200-food database from USDA, and writes the targets calculator, nutrient analyzer, optimizer, rounding ("6 bananas") and the advisor (fix suggestions for too-low and too-high nutrients) — all with automated tests.
- 🧑 You review a sample printout: Claude runs the engine on your real profile and liked foods and shows you the resulting weekly list and nutrient report in the terminal. You say what looks off.
- ✅ Done when: all tests pass and the sample week looks sensible to you.

## Phase 2 — iOS-style app shell + first deploy (Plan 2)

- 🤖 Builds the tab bar, This Week screen, Nutrient Report sheet, Now vs New sheet, Profile screen — saving data on the device for now. Sets up the Apple-style design system (fonts, colors, dark mode, grouped lists, sheets).
- 🧑 You create an empty GitHub repository (Claude tells you exactly which buttons), then in Vercel click "Add New → Project → Import" that repository → Deploy. From then on, every change Claude pushes goes live automatically in about a minute.
- 🧑 You open the Vercel link on your iPhone, test it, and report anything that feels un-iOS.
- ✅ Done when: you can plan a week on your phone (without recipes or trips yet).

## Phase 3 — Accounts & sync (Plan 3)

- 🧑 You create a Supabase project (Claude walks you through it) and copy two values (project URL and the public "anon" key) into Vercel's Environment Variables screen and a local `.env.local` file.
- 🤖 Adds login (email magic link), database tables with per-user security, and syncing of profile, foods, plans.
- ✅ Done when: you log in on phone and laptop and see the same data.

## Phase 4 — Recipes (Plan 4)

- 🤖 Recipe paste-reader, manual entry with USDA search (uses your USDA key, stored in Vercel's Environment Variables), review screen with ⚠️ lines, recipe library, recipes in the weekly plan with 1×/2× steppers, recipe-combination suggestions.
- 🧑 You paste 3–5 real recipes you like; Claude uses any that read wrong as new tests.
- ✅ Done when: your real recipes import correctly and show up in the plan.

## Phase 5 — Shopping trips (Plan 5)

- 🤖 Shopping schedule settings, trip splitting (days-covered proportions, freshness warnings), Shopping tab grouped by aisle with checkboxes, "I have this", per-trip eating guide.
- 🧑 You use it for one real shopping week and report what was awkward in the store.
- ✅ Done when: a real Tuesday + Friday week works end to end.

## Phase 6 — Supplements & bowls (Plan 6)

- 🤖 "I'll supplement this", dose suggestions under upper limits, daily supplement schedule with timing rules, "Suggest bowls" with shuffle.
- ✅ Done when: you can cover vitamin D / omega-3 by supplement and see when to take them.

## Phase 7 — Polish & install (Plan 7)

- 🤖 Installable home-screen app (PWA icon, offline mode, sync queue), loading/error states, final iPhone light/dark check.
- 🧑 On your iPhone in Safari: Share → "Add to Home Screen".
- ✅ Done when: it opens from your home screen like a normal app and works offline in the store.

---

## How each phase runs

1. Claude writes that phase's detailed plan → you skim and approve it.
2. Claude builds it task by task with tests, committing to git after each task.
3. A review pass checks the whole phase.
4. You try it (terminal printout in Phase 1, your phone from Phase 2 on) and give feedback.
5. Claude pushes it to GitHub → Vercel deploys it.
