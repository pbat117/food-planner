# Trip-by-Trip Planning, Shopping Tab and Recipes (Plan 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Replace week planning with continuous, trip-by-trip planning:
- shop every N days
- each trip gets its own short list
- nutrients balance over a rolling 7 days
- long-keeping food carries over in a pantry

Also fill the Shopping tab, and let the user add recipes by hand and put them into Regular items with times per week.

**Architecture:**
- **Engine:** gains `tripDays`, `windowDays` and `background` on `PlanInput`. Earlier trips' food is a fixed background contribution that doesn't count toward the food limit.
- **`tripPlan.ts`:** builds a trip's input from settings, history and pantry, runs `planWeek`, and works out what to buy (pantry first, packages for long-keepers).
- **AppState:** holds the current trip, trip history and pantry in localStorage.
- **Screens:**
  - **This Week becomes This Trip:** the trip list plus pantry, with a rolling 7-day report.
  - **Shopping:** the buy list with checkboxes and "I have this", plus a **Done shopping** button.
  - **Recipes:** add recipes by hand.
  - **Profile:** shopping rhythm, plus regular recipes listed with ×/week.

**Spec:** `docs/superpowers/specs/2026-11-04-nutrition-shopping-planner-design.md` §8 (revised 2026-11-05) and §8a.

## Global Constraints

- **No AI anywhere.**
- **Only what the user enters:** no default recipes or regular items, and no auto-picked whey.
- **Settings:**
  - `shopEveryDays` 1–7, default 3
  - `maxDistinctFoods` is now **per trip**, default 10, range 6–20
  - `nextTripDate` is an ISO date; empty means today
- **Rolling window:** windowDays = min(7, historyDays + tripDays), where historyDays = days of history overlapping the 7 − tripDays days before the trip. Targets scale by windowDays/7. Per-food caps (`maxWeeklyGrams`) and the fruit rule scale by tripDays/7.
- **Status:** "ok" at ≥ lowBelow, 90% (protein 100%).
- **Long-keeping** = `shelfLifeDays` ≥ 7. These are bought in whole packages (`package.grams`, else `unit.grams`), and the leftover goes to the pantry. Perishables are bought for the trip only.
- **Regular items:**
  - single food: weekly grams / 7 × tripDays, locked
  - regular recipe: ingredient grams × timesPerWeek / 7 × tripDays, locked
- Every list row shows grams beside estimated items. iOS look, 375 px, light and dark.
- History keeps only the last 14 days.

## Review Focus

1. **First trip with no history:** the window is just tripDays and the targets are N/7 of the week. Test: `first trip targets scale to N/7`.
2. **Pantry has enough rice:** buy 0 rice, but rice is still eaten and listed as "from your pantry". Test: `pantry covers the need → nothing to buy`.
3. **Corrupt trip history or pantry in storage:** ignored, and the app still plans. Test: `loadTrips/loadPantry reject garbage`.
4. **More "Your foods" due than fit in one trip:** cap at maxFoods − 2, longest absent first, and never infeasible. Test: `dueFoods caps and orders by absence`.
5. **Recipe deleted while it's a regular item:** the regular entry is dropped and planning works. Test: `deleting a recipe drops its regular entry`.

### Task 2: `tripPlan.ts`, planning one trip

**Files:** create `src/engine/tripPlan.ts`; test `tests/engine/tripPlan.test.ts`.

**Interfaces:**
```ts
interface TripRecord { date: string; days: number; daily: Record<string, number> }   // daily = grams per day eaten from this trip
interface TripArgs { base: PlanInput; date: string; days: number; history: TripRecord[]; pantry: Record<string, number>;
  regularLocks: Record<string, number> /* already scaled to the trip */ ; includeFoodIds: string[] }
function scaleTargets(t: WeeklyTargets, windowDays: number): WeeklyTargets      // target, lowBelow, max × windowDays/7
function historyWindow(history: TripRecord[], date: string, days: number): { amounts: Record<string, number>; days: number; seen: Set<string> }
function dueFoods(include: string[], seen: Set<string>, history: TripRecord[], date: string, maxFoods: number): string[]
interface TripPlan { date: string; days: number; plan: WeekPlan; buy: Record<string, number>; fromPantry: Record<string, number>; pantryAfter: Record<string, number> }
function buildTripInput(a: TripArgs): PlanInput
function purchase(items: RoundedAmount[], pantry: Record<string, number>): { buy; fromPantry; pantryAfter }
async function planTrip(a: TripArgs): Promise<TripPlan>
function finishTrip(t: TripPlan, history: TripRecord[], notBought: string[]): { history: TripRecord[]; pantry: Record<string, number> }  // keeps last 14 days
const addDays = (iso: string, n: number) => string
```

**Rules:**
- **`historyWindow`:** the window before the trip is [date − (7 − days), date). Each record contributes `daily × overlapDays`.
- **`dueFoods`:** included foods not in `seen`, ordered by days since last seen (never seen first), capped at `maxFoods − 2`.
- **`buildTripInput`:**
  - targets: `scaleTargets(base.targets, windowDays)`
  - `tripDays` = days, `windowDays`, `background` = window amounts
  - locks = regularLocks; `includeFoodIds` = due
  - supplements as base
- **`purchase`:**
  - Perishables: buy = eat grams.
  - Long-keepers: take from the pantry first. Buy whole packages for the shortfall; the leftover goes to `pantryAfter`.
  - Pantry foods not eaten carry over.
- **`finishTrip`:**
  - Appends `{date, days, daily: eat/days}`.
  - Drops records ending more than 14 days before the latest trip.
  - Pantry = `pantryAfter`, minus long-keepers in `notBought`: their purchase didn't happen, so subtract the bought amount, floored at 0.
